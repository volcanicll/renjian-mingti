# 「人间命题」参赛策划案

> **AI 出题，全人类作答。**
> 每天一道荒诞命题，三五个好友各拍一张，AI 当裁判兼毒舌点评，赢家拿走明天的出题权。

---

## 0. 电梯陈述（报名表用，30 秒版）

「人间命题」是一个基于微信群的摄影小游戏：每天系统抛出一道荒诞命题——"拍下你身边最没用的东西""拍一个正在努力工作的圆形物体"——玩家各自用十秒钟拍一张照片，匿名上墙后互相猜测"这张是谁拍的"，并投票选出"最绝奖"和"最敷衍奖"。AI 全程参与：帮没灵感的人生成命题、判定照片是否跑题、给每张作品写一句毒舌短评。本局赢家获得下一局的出题权，命题就这样在人与人之间流转。它不需要庞大的用户基数——**一局游戏的最小单位只是一个微信群**。

---

## 1. 为什么是这个点子

### 1.1 创意内核

把"摄影"从技能竞赛还原为**观察力与脑洞的社交货币**。拍照是全民都会且每天都在做的事，缺的从来不是技术，而是一个"为什么要拍这张"的理由。「人间命题」每天提供这个理由，并用熟人社交 + AI 点评让每一张随手拍都有观众、有回响、有笑点。

### 1.2 查重结论与差异化

| 竞品 | 形态 | 它做的事 | 与我们的本质差异 |
|---|---|---|---|
| Neat Photo | App | 每日摄影主题挑战 + AI 从构图/曝光角度评分 | 它教人**拍得好**，我们只在乎**想得妙**；零门槛，无评分压力 |
| Let's Pics（日本黑客松） | Web | 每日命题拍照学英语 | 命题只是英语学习的载体，无社交局概念 |
| 你画我猜类小游戏 | 小程序/App | 熟人局 + 创作猜谜 | 需要绘画能力；我们把画笔换成了人人自带的摄像头 |

**核心差异一句话：别人做的是"摄影产品"，我们做的是"用摄像头玩的派对游戏"。**

### 1.3 为什么是现在

多模态大模型已成熟到可以可靠地完成两件事：判定一张照片"是否符合一句荒诞命题"，以及写出有梗的短评。这两件事在两年前做不到，所以这个玩法此前无法成立。同时，微信小程序的群分享链路是所有平台中裂变成本最低的，与"小局制"天然契合。

## 2. 核心玩法：一局的完整流程

```
 发起人创建一局
   ├─ 抽一道官方每日命题，或
   ├─ 自己出题，或
   └─ 让 AI 代出（三选一）
        │
        ▼
 转发到微信群 ──► 朋友点卡片进入，各拍一张上传
   （局有时限：默认 24 小时，也可设"人齐即开"）
        │
        ▼
 揭晓环节（匿名墙）
   ├─ 第一步：猜猜这是谁拍的 ── 猜对越多，结算加分
   └─ 第二步：投票（不能投自己）
        ├─ 🏆 最绝奖：脑洞最大
        └─ 🍬 最敷衍奖：明摆着应付（同样是荣誉）
        │
        ▼
 结算页
   ├─ AI 毒舌短评逐张揭晓（笑点高潮）
   ├─ 最绝奖得主获得下一局出题权 ◄── 留存钩子
   └─ 自动生成战报海报（带小程序码）
        │
        ▼
 海报发回群里 / 朋友圈 ──► 新玩家扫码 ──► 新的一局
```

### 2.1 设计要点

- **异步回合制**：全程不需要实时长连接。创建、拍摄、揭晓、投票都是异步状态流转，技术上极稳，体验上也符合微信群"想起来就玩一把"的节奏。
- **匿名墙是笑点放大器**：先猜人再投票，两层互动都建立在"原来你是这么理解这道题的"的认知反差上。
- **最敷衍奖与最绝奖同等荣耀**：故意保护低水平参与者——敷衍得恰到好处也是一种才华。这保证了不擅长拍照的人也敢交作品。
- **命题权流转**：赢的人获得出题权，出题权是游戏里唯一的"权力"，驱动用户回流。
- **单机也有内容**：即使一个人，每天也能收到官方命题并拍摄存档，AI 会认真点评你的每张照片——参与度的下限不是零。

## 3. AI 的三个角色

| 角色 | 职责 | 实现方式 |
|---|---|---|
| **① 出题人** | 为没灵感的人生成荒诞命题；维护官方每日题库 | 文字模型 + 风格池（具体物件 / 抽象概念 / 荒诞限定三类），示例见下 |
| **② 裁判** | 内容合规初审 + "是否符合命题"判定 | 图片安全审核接口 + 多模态模型判定，返回 通过/存疑/跑题 三档 |
| **③ 点评员** | 给每张作品写一句毒舌或诗意短评 | 文字模型，输入 = 命题 + 照片描述，输出限一句话 |

**裁判的分寸感（关键设计）**：AI 只淘汰明显跑题和违规的照片，"存疑"的一律放行交给玩家投票裁决。AI 是暖场主持人，不是独裁评委——它永远不告诉用户"你拍得不好"，只说"你这理解很清奇"。

**命题风格池示例**：

- 具体物件型："拍下你家最有资历的物品""拍一个正在努力工作的圆形物体"
- 抽象概念型："拍下今天的风""拍下'等一下'""拍下你身边的红色"
- 荒诞限定型："拍下一样东西，让它看起来值一个亿""拍下最没用的超能力现场"

**点评员输出示例**：

> 命题：「拍下今天的风」
> AI 点评："摄影师坚称风来了。作为证据，他提供了一棵树和一段模糊的信仰。"

> 命题：「拍下你家最有资历的物品」
> AI 点评："这把伞 2019 年入职，主要成就是三次被遗落在地铁仍坚守岗位。"

这些短评是整个产品的传播素材核心——用户会为了看 AI 怎么吐槽自己而交作品，会为了分享吐槽而发朋友圈。

## 4. 产品结构与技术方案

### 4.1 页面结构（5 个主页面）

1. **首页**：今日官方命题 + 我进行中的局 + 创建入口
2. **局内页**：命题展示、倒计时、拍照上传（复用 wx.chooseMedia）
3. **揭晓墙**：匿名瀑布流 → 猜人 → 投票
4. **结算页**：奖项揭晓、AI 短评逐条弹出、战报海报生成
5. **年鉴**：历史最佳作品汇聚（全局画廊，随规模成长）

### 4.2 技术选型

- **前端**：uni-app（Vue3）编译至微信小程序，与项目仓库 wechat-uni 一致
- **后端**：微信云开发（云函数 + 云数据库 + 云存储），个人开发者零运维
- **AI 接入**：云函数中转调用多模态大模型 API（密钥不落地前端）；判定与点评各封装独立云函数，便于分别控制成本
- **消息触达**：微信订阅消息（"你参与的局已揭晓""你的照片被投了最绝奖"）
- **海报**：Canvas 2D 合成战报图 + 小程序码

### 4.3 数据模型（云数据库集合）

| 集合 | 关键字段 |
|---|---|
| users | openid、昵称头像、战绩（胜场/最绝次数/最敷衍次数） |
| rounds | 命题文本、命题来源(official/custom/ai)、状态(created→shooting→revealed→closed)、发起人、截止时间、赢家 |
| entries | roundId、上传者、图片 fileID、AI 判定结果与理由、AI 短评、票数、所获奖项 |
| votes | roundId、投票人、目标作品、标签(best/lazy) |
| guesses | roundId、猜者、目标作品、猜的人、是否命中 |
| prompts | 官方题库：文本、来源(人工/AI 自进化)、使用日期 |

### 4.4 关键技术点

- **匿名打乱**：揭晓墙由服务端打乱顺序下发，剥离作者字段，结算时才回填。
- **AI 判定 Prompt 策略**：要求模型输出 JSON `{verdict, confidence, reason}`，confidence < 阈值一律归为"存疑"放行；reason 用于在揭晓时展示"AI 的判词"，本身也是娱乐点。
- **成本控制**：判定只在提交时调用一次；短评在结算时批量生成；官方题库由 AI 离线批量预生成入库，运行时零调用。

## 5. 四周开发排期

| 周 | 目标 | 交付物 | 里程碑 |
|---|---|---|---|
| W1 | 地基 | 云开发环境、openid 用户体系、创建/分享/进入一局、拍照上传 + 内容安全审核 | 能在两个手机间完整传一张照片进同一局 |
| W2 | 玩法闭环 | 揭晓墙、匿名打乱、猜人、投票、结算、命题权流转、订阅消息 | 一局可以从头玩到尾 |
| W3 | AI 上场 | 出题/判定/点评三个云函数、战报海报、年鉴页、首页打磨 | AI 短评达到"愿意截图发朋友"的水准 |
| W4 | 上战场 | UI 细节、真机兼容测试、埋点、种子数据预跑、答辩材料与 demo 彩排 | 提交作品 + 彩排通过 |

排期原则：W2 的玩法闭环优先级高于一切——AI 可以晚一周上线，但"一局能玩通"必须最早成立，它是所有演示和运营的前提。

## 6. 冷启动与运营方案

### 6.1 参与度金字塔（本方案的核心论证）

```
        ┌────────────┐
        │  年鉴/排行榜 │  ← 全局层：规模上来后自然成立，不承诺、不依赖
        ├────────────┤
        │   熟人小局   │  ← 主战场：3-5 人即满员开饭，冷启动下限 = 一个微信群
        ├────────────┤
        │ 单机每日一拍 │  ← 保底层：一个人也有官方命题 + AI 认真点评
        └────────────┘
```

传统 UGC 社区的死因是把第一层当成了全部。本产品把第二层做成核心：**拉新单位从"一万注册用户"降维到"一个宿舍群"**。

### 6.2 种子期动作（赛前两周）

- 用自己的 3 个真实群（同学/同事/家人）跑一周，积累 ≥50 局真实数据与作品库；
- 每天亲自扮演"出题人"和"点评转发者"，把最好笑的战报海报手动扩散到相邻群；
- 找 1 个校园社团或公司部门做"命题日"合作，定向灌入一批同好用户。

### 6.3 传播设计

- **战报海报即获客素材**：每局结算海报自带小程序码和"最绝奖作品"，好笑的内容自己会长腿；
- **订阅消息召回**：被投票、被点名、轮到你出题——三个钩子覆盖全部回流场景；
- **年鉴 H5 化**（赛后可选）：把"年度人类观察报告"做成可分享长图。

### 6.4 大赛现场 Demo 策略（90 秒脚本）

1. **0-10s** 开场提问："各位评委今天上班路上拍了多少张照片？零张？那太可惜了，因为没有任何一张照片值得你们拍。"——引出"缺的不是能力，是理由"。
2. **10-45s** 现场开局：请评委用手机扫码进入同一局，命题"拍下你现在看到的最无聊的东西"，倒计时 60 秒。
3. **45-75s** 揭晓墙投屏：匿名照片逐张弹出，AI 毒舌短评同步朗读——全场笑点所在。
4. **75-90s** 收尾：投票选出"最绝奖"，指出赢家获得了出题权，然后一句话讲愿景："我们想让每天多一张值得拍的照片。"

## 7. 风险与合规

| 风险 | 应对 |
|---|---|
| UGC 类目资质：个人主体小程序无法开通社区类目 | 使用大赛提供的企业主体报名；若不可行，以"工具+好友互动"形态申报并弱化公共广场属性（年鉴仅展示精选） |
| 内容安全 | 双审：图片过微信内容安全接口 + AI 判定前置过滤；保留举报入口与黑名单机制 |
| 肖像权 | 规则页明确"请勿未经同意拍摄他人"；揭晓墙提供一键删除与举报 |
| 作品版权 | 用户协议约定：上传作品授权平台在年鉴/战报中展示，作者署名权归用户 |
| AI 成本失控 | 题库离线预生成；判定/点评按次计费上限熔断；免费额度内设计每日游玩上限 |

## 8. 命名与文案

- **主案**：「人间命题」——"人间"对应烟火气与众生相，"命题"对应考试作文的既视感，自带幽默。
- 备选：「今日命题」「命题局」「拍了什么」「人类观察作业」
- 宣传语候选：
  - "每天一道题，考的不是摄影，是脑洞。"
  - "你和艺术家之间，差的可能只是一道命题。"
  - "AI 都替你点评好了，就差你按下快门。"

## 9. 结语：为什么它能赢

三个维度各有一句答辩可以直接用的话：

- **创新性**：市面上的拍照产品都在教人拍得更好，我们是第一个把摄像头变成派对道具的——而且"命题权在人之间流转"的机制此前没有产品做过。
- **有趣 & 易参与**：十秒一张照片、一个微信群就能开局、敷衍也能拿奖——参与门槛被压到了地板上。
- **可行性**：异步回合制无需实时服务端，云开发免运维，AI 只承担三个边界清晰的轻任务，个人一个月可交付完整闭环。
